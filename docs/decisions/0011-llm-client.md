# 0011 — LLM client, provider and structured output

## Context
M1 turns documents into `po_extraction.v1` (SPEC F2, §9) with an LLM. CLAUDE.md requires every call to go through one client (`LLMClient`), model ids from env, and `prompt_version`, model, latency and cost stored per call. CI must never call a paid API (M1 plan, Q9). The owner chose **Anthropic** (Q1, 2026-11-14): Claude Sonnet for extraction, Claude Haiku for spreadsheet column mapping. This ADR covers the client (PR 2). Prompt loading, the schema retry and grounding come with PR 3, which will extend this ADR or add one. The other M1 ADRs (0010, 0012–0015) are a Follow-up.

## Decision
- **One Protocol, `app/llm/client.py`**: `LLMClient.extract(StructuredRequest[T]) -> LLMResult[T]`. The request carries the system prompt, the content parts (text, images as bytes + MIME), the output Pydantic model, `prompt_version`, `schema_version`, model, `max_output_tokens` and effort. Document content goes only into the user turn. A result has an `outcome`: `ok`, `invalid_output`, `refusal` or `truncated`. All four are billed calls, so all four are results (with tokens and cost), not exceptions, and every paid call can be recorded. Transport failures raise `LLMError` with a stable code (`llm_timeout`, `llm_rate_limited`, `llm_unavailable`, `llm_auth`, `llm_bad_request`, `llm_provider_error`, `llm_config`, `llm_replay_miss`). The provider's message text is never kept: it can quote the request.
- **Adapter on the official `anthropic` SDK** (`app/llm/providers/anthropic.py`, the only module that imports it). Pinned `~=2.3.0` (upgrades stay deliberate), locked at 2.3.0 (released 2026-10-23). Newer 2.x releases were less than two weeks old when this was written.
- **Structured output = `output_config.format` (JSON schema)** built from our Pydantic model. The API supports only a subset of JSON Schema (no `minimum`/`maximum`, `minLength`/`maxLength`, `pattern`), so the SDK's `transform_schema` moves those constraints into the field descriptions. Our model validates the response again and enforces all of them. A test pins the subset: no unsupported keyword, every object has `additionalProperties: false` and requires all its keys.
- **No tools, no sampling parameters, no thinking override.** API version `2026-10-21` rejects `temperature`/`top_p`/`top_k` on every model, and the current models can't all turn thinking off the same way (Sonnet 5.5 rejects `disabled`). Each model keeps its default (adaptive) thinking. Depth and cost are set by `output_config.effort` (`LLM_EFFORT`, default `medium`), tuned with evals in PR 9. Thinking tokens are billed as output, so the stored cost covers them.
- **No refusal fallback** (owner, 2026-11-15). The API's `fallbacks` would answer with another model, which breaks the cost table and eval reproducibility. A refusal is `outcome=refusal`; the document fails.
- **Transport retries are the SDK's** (`max_retries` = `LLM_MAX_RETRIES`, default 2): connection errors, 408/409/429/5xx, honouring `retry-after`. 4xx other than 408/409/429 are not retried.
- **Timeouts never pay twice for one reply** (`sec` M1). A timed-out non-streaming reply has likely been generated and billed already.
  - `LLM_TIMEOUT_SECONDS` (per attempt, default 600) must cover a full-length reply: at least the SDK's own estimate, 3600 s × `LLM_MAX_OUTPUT_TOKENS` / 128,000 (450 s for 16,000). Settings refuse a shorter value.
  - The whole call, SDK retries included, is bounded by our deadline: one attempt + 60 s. This leaves room for quick 429/5xx retries and also caps the SDK's unbounded `retry-after` sleep.
  - The SDK's own per-attempt timeout is set 30 s beyond the deadline, so the SDK never sees a timeout and never re-sends a timed-out request: our deadline always fires first (`sec` delta). A test with `max_retries=2` checks that a reply that never comes is sent exactly once.
  - A deadline hit is classified by what the call saw: requests sent and statuses received, counted by httpx2 request/response hooks, per task. If a request was still waiting for its reply, it may already be generated and billed, so it's `llm_timeout`. The same goes for a 2xx whose body was still being read when the deadline hit. Only when every request got an error answer (the deadline hit while the SDK slept before a retry) is it transient: `llm_rate_limited` if a 429 was seen, otherwise `llm_unavailable` for other retryable statuses. `llm_timeout` is **not** transient: the job queue (PR 12) doesn't re-run it and must send the document to a visible failed / needs-attention state.
  - Accepted residual: the SDK re-sends after a connection reset in the middle of reading a 200 body (`APIConnectionError`). That re-send could be billed, but it's rare because a non-streaming reply arrives all at once (`sec`, 2026-11-15).
  - PR 12's lease must be longer than the deadline (11 min with the defaults). The schema retry (one more call with the sanitized validation errors, SPEC §9) is separate and comes in PR 3.
- **Nothing is taken from the environment by the SDK.** The key (`LLM_API_KEY`) is passed explicitly, so the SDK reads no `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/profile. The base URL is pinned to `https://api.anthropic.com`. The HTTP client is built with `trust_env=False`, so CA-bundle env vars (`SSL_CERT_FILE`, …) are ignored. It also has every proxy mount set to none, because the SDK builds proxy mounts from `HTTPS_PROXY`/`ALL_PROXY` (and the Windows registry) whatever `trust_env` says. A test checks that `api.anthropic.com` goes through the default transport with those vars set. OpenTelemetry is off (`open_telemetry=False`), so no env var can turn on span content. The adapter refuses to start if `ANTHROPIC_BASE_URL` (the key would go elsewhere), `ANTHROPIC_CUSTOM_HEADERS` (merged into every request, can't be disabled) or `ANTHROPIC_LOG` (SDK request logging outside our redaction) is set. The `anthropic` logger is capped at WARNING.
- **Settings.** `LLM_PROVIDER` (`anthropic|fake`), `LLM_API_KEY` (SecretStr), `LLM_EXTRACTION_MODEL`, `LLM_MAPPING_MODEL`, `LLM_TIMEOUT_SECONDS` (120), `LLM_MAX_RETRIES` (2), `LLM_MAX_OUTPUT_TOKENS` (16000, non-streaming), `LLM_EFFORT` (`medium`). The key and model are checked only by `app.llm.factory.create_llm_client`, which only the worker and `evals --live` call: the API process never needs the key. `fake` is refused unless `APP_ENV=local` and not deployed.
- **Cost** (`app/llm/pricing.py`): USD per 1M tokens per model id, with the date it was checked against the pricing page (2026-11-15): Sonnet 5.5 $2 / $10; Haiku 5.5 $0.10 / $0.50 up to 100,000 prompt tokens, and $0.50 / $2.50 for the whole request above that. An unknown model gives `cost_usd = None` plus an `llm.unknown_model_price` warning, never a guess. Tokens are stored too, so cost can be recomputed.
- **Test doubles** (`app/llm/fake.py`): `FakeLLMClient` (scripted), `ReplayLLMClient` (cassettes keyed by `StructuredRequest.fingerprint()`, a SHA-256 over prompt_version, schema_version, the output schema itself, model, effort, max tokens, system prompt and content, with images by hash; a missing, foreign, edited or malformed cassette is `llm_replay_miss`, never a live call or a crash) and `RecordingLLMClient` (writes cassettes; evals `--live --record` only). A cassette holds the output text, stop reason, usage, model, latency and request id: never headers, the key or the prompt. Fake and replay go through the same parsing, cost and logging code as a live call.
- **No network in unit tests.** An autouse fixture blocks the real `httpx2` transports, so the SDK can't leave the machine. Adapter tests inject `httpx2.MockTransport`. SDK 2.x uses the `httpx2` fork, and mocks built on plain `httpx` would silently not apply. Tests marked `live` are deselected by default and skipped unless `RUN_LIVE=1`, whatever `-m` says, so they never run in CI; one manual smoke test exists (`tests/llm/test_anthropic_live.py`, well under $0.01).
- **Logging.** One `llm.call` line per call: provider, model, prompt/schema version, outcome or error code, stop reason, latency, tokens, cost, number of validation errors, provider request id. Never the prompt, the content, the output or provider error text.

### Prompts, extraction core and injection defenses (M1 PR 3, 2026-11-16)
- **Prompt files** (`app/llm/prompts.py`): `app/prompts/<name>/v<N>.md` with `## System`, `## User` and optional sections (`## Retry`). Placeholders are `{{lower_snake}}`; the system section may have none, so document data can never reach the system prompt. Substitution is strict (missing or unknown value = error) and single-pass (a value containing `{{x}}` stays literal). Malformed files fail to load. Each call records `prompt_version` (`<name>/v<N>`); the result also carries the SHA-256 of the file with LF line endings, so a Windows checkout hashes the same. `extract_po/v1` was rewritten in place (Q15: never used); versions become immutable with the first committed baseline (PR 9 pins the hashes).
- **Message layout** (`app/extraction/extract.py`): the document goes only into the user turn, inside `<document_ID>…</document_ID>`, with the metadata (`sender_email`, `received_at`) in a `<metadata>` block inside it. Page images sit between the two text parts, inside the block.
  - **`ID`** is the first 16 hex characters of a SHA-256 over the whole input (text, image hashes, metadata). The prompt says only the closing tag carrying that code ends the document.
    - A document can't contain the hash of itself, so it can't forge the closing tag. That holds whatever look-alike characters it uses, and also for text printed on page images (`sec` M2, L1).
    - The ID is deterministic, so replay cassettes still match.
  - **Document text:** CRLF → LF, and C0/C1 controls are removed (tab and newline kept). Any `<document`, `<metadata` or `<validation_errors` tag, opening or closing, gets its first character turned into `&lt;`. This also catches:
    - spaces or invisible characters before the slash and between any two letters of the name. "Invisible" means every Unicode Cf/Zs/Zl/Zp character plus the combining grapheme joiner and variation selectors, built from code points at import;
    - look-alike `<` (fullwidth, small form, angle brackets) and look-alike `/` (fullwidth, division and fraction slash).
  - **Role headings:** a line starting with one or more `#` (or the fullwidth `＃`, invisible characters allowed) followed by `system`/`user`/`assistant`/`retry` gets a leading backslash.
  - Nothing else is changed, so `raw_text` stays faithful.
  - **Linear time:** every repeated gap is possessive (`*+`). The first version backtracked quadratically: `<` followed by 16k spaces took 3 s (`sec` H1). It now runs in linear time, tested on 200k-character hostile inputs.
  - **Metadata:** every control or format character becomes a space, whitespace is collapsed to one line, delimiters are neutralized, and the length is capped (254 for the email, 64 for the time). A missing or empty value is written as `unknown`.
  - **One delimiter of each kind:** the prompt prose doesn't spell out the tags, so each delimiter appears exactly once in the user turn. Tests check this after NFKC, look-alike folding and removal of invisible characters.
- **Schema retry once** (SPEC §9): only `invalid_output` is retried. The second request is the first one plus a text part from the `Retry` section. It lists the sanitized validation errors (path, type, fixed message; never input values) inside a `<validation_errors>` block labelled as data, with `&`, `<` and `>` escaped (M1-L3). For `extra_forbidden` the path is withheld, because the key name is model-chosen and may echo document text; every other path is made only of our schema's field names (`sec` L4). A second invalid answer is `failed` / `schema_validation_failed`. `refusal` → `llm_refusal` and `truncated` → `llm_truncated` are final, with no retry and no fallback. The retry resends the whole document (the owner accepted the cost on 2026-11-16; prompt caching is Follow-up M1-CACHE).
- **Billed calls are never lost.** The result carries every `LLMResult` in order. A transport `LLMError` is raised as `ExtractionCallError`, which carries the calls made before it, so the worker (PR 14) can store each one.
- **Grounding** (`app/extraction/grounding.py`, Q16): only for inputs with a text layer. Each non-null `customer_po_number`, `order_total`, part number (customer and vendor), `qty`, `unit_price` and `extended_price` must appear in the source text, or it gets an `ungrounded` warning (code + field path, never a value). Values are never changed or blanked.
  - Identifiers are matched case-insensitively with whitespace removed (NFKC).
  - Numbers are matched by value, ignoring `$`, thousands separators and the sign.
  - Matching errs toward fewer warnings, because false alarms teach reviewers to ignore the flag. Image-only inputs are skipped.
  - Numbers are compared exactly (`Decimal(str)` and `copy_abs()`, no context), so a huge number can't raise `Overflow`. A number with more than 40 digits never matches.
  - `ExtractionResult.grounding_checked` says whether the check ran. It is false for image-only input, or when the check itself failed, in which case it logs `extraction.grounding_failed` with the error type only and the extraction and its billed calls are kept (`sec` M1, L2). So "no warnings" never means "checked" by itself.
  - **Limits:** grounding catches values the model made up, not injection, because a value an attacker printed is in the document. Small numbers are almost always found somewhere on the page (page numbers, dates).

## Consequences
- Adding a provider means adding a module in `providers/`. The Protocol, doubles, pricing and logging stay the same.
- A model change in env changes the fingerprint, so replay fails until a live run records new cassettes (Q9 enforcement, PR 8/9).
- The SDK is a runtime dependency of the API image, even though only the worker uses it. The factory imports it lazily, so the API process doesn't load it.
- SDK upgrades are deliberate: the refused-env list and the transport mock depend on SDK internals, and tests pin both.
