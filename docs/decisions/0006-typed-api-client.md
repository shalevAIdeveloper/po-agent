# 0006 — Typed API client generated from OpenAPI

## Context
CLAUDE.md requires data fetching through a typed API client. Hand-written TypeScript types drift from the FastAPI models silently.

## Decision
- The API's OpenAPI schema is committed at `apps/api/openapi.json`, generated by `uv run python -m app.openapi_export openapi.json` with local settings (independent of the environment). A pytest test fails if the committed file is stale.
- The web generates `apps/web/src/lib/api/schema.d.ts` with `pnpm gen:api` (openapi-typescript); the file is committed and excluded from ESLint. CI regenerates it and fails on any diff; the web job also runs when `apps/api/openapi.json` changes.
- The client keeps Zod schemas for runtime validation of responses, declared with `satisfies z.ZodType<components["schemas"][...]>`, so they fail to compile if they drift from the generated types.

- Limitation: `satisfies` catches a field the API adds or retypes, but not one the API removes (extra keys in the Zod output still type-check). Removed fields surface as compile errors only where the web reads them; add a key-equality type test if that proves insufficient.

## Consequences
- An API model change shows up as a reviewed diff in both `openapi.json` and `schema.d.ts`, and as compile errors where the web relies on changed fields.
- Two regeneration commands to remember; CI points at them when they are forgotten.
