# 0012 — Document inputs: detection, parsers, caps and isolation

## Context
M1 turns an uploaded file into the input of the extraction core (`DocumentInput`: a text layer and/or page images, plus untrusted metadata; ADR 0011). Every file is untrusted input (principle 3) and goes through native parsers. The owner decided (Q2, Q12, 2026-11-14): PDF (text and scanned), PNG/JPEG and EML body in M1; XLSX/CSV in PR 5; HEIC and EML attachments in M6; at most 20 PDF pages; 20 MB per file (SPEC §10). The owner's answers on the PR 4 plan (2026-11-16) are recorded below. This ADR covers M1 PR 4, including its `sec` and `qa` review fixes. PR 5 adds the spreadsheet path to it.

## Decision
- **Type from the bytes only** (`app/extraction/inputs/detect.py`). The filename and the declared Content-Type are never read.
  - PNG and JPEG by their signatures.
  - PDF by `%PDF-` at the start, or within the first 1 KB (checked after the EML test).
  - EML by its header block, read within the first 64 KB: RFC 5322 field lines up to a blank line, with `From` and at least two known email fields. An mbox `From ` separator as the first line is allowed.
  - XLSX/XLSM (a ZIP), legacy Office files (CFB) and CSV: see "Spreadsheets" below (PR 5).
  - Everything else is `unsupported_type`: HEIC, GIF, WebP, any other ZIP or CFB.
- **Caps** (`limits.py`, one place):
  - 20 MB per file (`file_too_large`), checked before detection and before any child process starts.
  - 20 PDF pages (`too_many_pages`), checked before any page is loaded.
  - 60 MP per uploaded image, read from the header before decoding (`image_too_large`). Pillow's `MAX_IMAGE_PIXELS` is set to the same value, and its bomb warning is turned into an error, as a backstop. Each guard is tested without the other.
  - 200,000 characters of text (`document_too_large`). A PDF's text is checked page by page, before each page is rendered. HTML over 5 M characters is refused before conversion.
  - 20 MiB of page images per document (`document_too_large`). The adapter base64-encodes images, so that is about 26.7 MiB on the wire, plus at most about 0.8 MB of text, which keeps one request under the provider's 32 MB limit. A test pins this arithmetic.
- **Images sent to the model** (`image.py`):
  - Only Pillow's PNG and JPEG decoders are used. A phone's multi-picture JPEG (MPO) opens through the JPEG decoder, and only its first picture is used.
  - EXIF orientation is applied, transparency is flattened onto white, and the long side is cut to 1568 px.
  - Every image is **re-encoded** from a fresh RGB image: no EXIF (GPS), ICC, XMP or text chunk leaves the parser.
  - Pages are encoded as PNG for sharp text, or as JPEG at quality 85 when the PNG would be over 1 MB.
- **PDF** (`pdf.py`, pypdfium2 `~=5.14.0`, which bundles PDFium without JavaScript or XFA):
  - Text layer page by page, each page under a `[page N]` line, so the model can fill a line's `page`.
  - Every page is rendered with its forms at 150 dpi, but never more than 1568 px on the long side. The scale is computed from the page box before rendering, so a 200-inch page can't allocate a 900 MP bitmap.
  - Fewer than 20 non-space characters of text in the whole file means a scan: `text=None`, images only, and grounding is skipped.
  - **A PDF that needs a password to open** is `unsupported_pdf`. **A PDF with only an owner password** (no printing or copying, but opens without a password) **is read normally** (owner, 2026-11-16).
  - Known gaps:
    - Values typed into form fields are drawn on the page image but are not in the text layer, so grounding may flag them. That is a false alarm the reviewer can see, never a changed value.
    - Text can be in the text layer without being visible (render mode 3, white text). OCR'd scans rely on that, so it is kept. See "What the reviewer sees" below.
- **EML** (`email.py`, stdlib, `policy.default`):
  - **Body:** the `text/plain` part. If there is no plain part, or it is blank, the `text/html` part is converted to text instead (`qa`): `script`/`style`/`head` dropped (and a `<body>` tag always ends the head, since HTML5 lets `</head>` be left out), block tags become line breaks, table cells become tabs, whitespace collapsed as a browser would show it. Nothing referenced by the HTML is ever fetched.
  - An unknown charset or undecodable bytes are replaced, not fatal.
  - **Attachments are not read**, and that includes a forwarded message (`message/rfc822`) (owner, 2026-11-16). Their presence adds the warning `attachments_ignored`, never their names.
  - **Warnings for text the reader can't see** (`sec` M3, strengthened after `sec` delta L-7):
    - `alternative_parts_differ` when the plain and HTML versions carry different numbers, or the same numbers in a different order. The model reads the plain text, while a mail client shows the HTML.
    - `hidden_html_text` when the HTML hides elements, whichever part was read: the `hidden` attribute, or a style (inline or in a `<style>` rule whose selector the markup uses) with `display:none`, `visibility:hidden|collapse`, `mso-hide:all`, `opacity` under 0.1, `max-height:0` or a font under about 2px.
    - These are heuristics, not a renderer, and they can be evaded (an external stylesheet, white on white, positioning off screen). They are a backstop: the guarantee is that the reviewer sees the text the model read (below).
    - Hidden text is kept, not removed. The reviewer sees the warning.
  - **`From` and `Date` are claims anyone can forge.** They are kept as `claimed_from` (the address part only) and `claimed_date` (only a date with a time zone), **for display only** (owner, 2026-11-16).
    - They also go into the prompt as untrusted metadata, inside the document block (ADR 0011).
    - A `From` with control or format characters, or that isn't valid UTF-8, becomes `None`. So does a `Date` outside 1990 to tomorrow, or one that can't be converted to UTC (`sec` L1).
    - **Nothing may store them as the received time, identify the customer, choose a price list or decide anything from them.** M6 email intake identifies the customer by the receiving channel and by sender authentication checked by our own receiving server, never by the `From` text (Follow-up M6-FROM).
- **What the reviewer sees** (`sec` M3): the review screen (M3) shows the text the model actually read, plus the page images. It never shows a rendered HTML email. So text the model used is never hidden from the reviewer (Follow-up M3-SOURCE).
- **Errors are codes** (`errors.py`): `unsupported_type`, `file_too_large`, `too_many_pages`, `unsupported_pdf`, `invalid_file`, `image_too_large`, `empty_document`, `document_too_large`, `parse_timeout`, `parse_failed`, and from PR 5 `too_many_rows`, `unsupported_spreadsheet`, `encrypted_spreadsheet`. `messages.py` maps every code to a fixed sentence for the user (a test checks that no code lacks one and that no message carries file data); PR 13 returns it with the 415/422 and PR 15 shows it. Any other exception from a parser becomes `invalid_file`; its class name goes to the log, its message never does (it can quote the file). `MemoryError` is `parse_failed`.
- **Isolation** (`isolate.py` + `child.py`, owner, 2026-11-16; hardened after `sec` M1, M2, L4 and the `sec` delta review): the worker parses in a **child process started with `subprocess`**.
  - The child is a fresh `python -I -B` interpreter with an **empty environment**: only `PATH` (on Windows `%SYSTEMROOT%\System32`, never the current directory), plus `SYSTEMROOT` on Windows. Nothing secret is passed to it; a test checks this. (`multiprocessing`'s `spawn` copied the whole environment.) The app directory is appended to `sys.path`, so it can't shadow the stdlib, and only an `app.*` or `tests.*` parser can be named.
  - **The child runs as the worker's user**, so an empty environment alone isn't enough: a compromised child could read the worker's `/proc/<pid>/environ` (`DATABASE_URL`, `LLM_API_KEY`) or memory (`sec` delta M-A). On Linux the worker makes itself **non-dumpable** (`prctl(PR_SET_DUMPABLE, 0)`) before its first child; a Linux test checks that the child gets "permission denied". This doesn't cover processes that started the worker, so **the worker must be `exec`ed** with no shell or launcher holding the secrets (the API's `sh -c "exec …"` already does this; PR 14 keeps it for the worker). Root in the container would bypass it; the image runs as uid 10001.
  - The file goes in on stdin. No other descriptors are inherited, and stderr goes to devnull.
  - On Linux the child sets, before reading the file and as hard limits: a 2 GiB address space, a CPU-time backstop (timeout + 15 s), and **no new processes** (`RLIMIT_NPROC` 0), so nothing it starts can hold the reply pipe open or outlive it. That also forbids threads: parsers must not start any, and a future dependency with a thread pool (numpy/OpenBLAS) needs `*_NUM_THREADS=1` in the child environment. Docker (runc) enforces these limits and the `prctl`; that Railway's runtime does too is checked by a deploy smoke check (Follow-up M1-PARSE-NET).
  - On POSIX the child runs in its **own session**; when the parse ends, for any reason, the parent kills the whole process group (`sec` delta M-B). The parent waits on the process with the deadline, never on its stdout closing, and without reaping it (`waitid` with `WNOWAIT`) until the group is killed, so the group id can't have been reused by then.
  - The child answers with a **JSON header plus raw image bytes** (`wire.py`, UTF-8 JSON), never a pickle. The parent checks the reply like untrusted input: allowed literals, types, lengths that add up, the same caps as the parsers, and the same sanitizing (text without NUL and valid UTF-8, a `claimed_from` with `@` and printable, a `claimed_date` in range). The parent reads at most the largest valid reply size.
  - After 60 s the child is killed (`parse_timeout`). A non-zero exit, no answer, too much output, an unfinished reply (something outside the group still holds the pipe) or a malformed reply is `parse_failed`. Tests cover a hang, a crash, a raised exception, garbage output, a flood, a child that closes stdout and keeps running, and a grandchild holding the pipe.
  - **Not covered:** the child can still use the network, and on Windows (dev only) there is no process group or job object. Follow-up M1-PARSE-NET (seccomp/Landlock or a network namespace for the child).
- **Logging**: one line per document, `document.parsed` or `document.parse_rejected`, with kind, size, page and image counts, text length, warning codes and error code. Never a filename, text, header value or parser message. The parent logs; the child doesn't. `ParsedDocument` and `ParsedEmail` hide their content from `repr`.
- **Dependencies**:
  - Runtime: `pypdfium2~=5.14.0` (released 2026-10-04) and `pillow~=13.0.0` (2026-10-17). The newer 5.15.x was under two weeks old.
  - Dev only: `reportlab~=5.1.0`, so the tests build every PDF (including encrypted ones and forms) in code. No binary test files are committed. The image smoke check (`smoke-images.sh`) fails if `reportlab` is installed in the API image.
  - PR 5 adds `openpyxl` and `defusedxml` (see "Spreadsheets").

### Spreadsheets (M1 PR 5, owner decisions 2026-11-16)
SPEC F2: a spreadsheet is parsed by code, and the model only maps columns. The parser runs in the same child process as above (timeout, memory, empty environment, parent-side checks), and its result is a cell table, not text.

- **No pandas** (Q-PR5-1): XLSX is read with **openpyxl in read-only mode**, CSV with the **stdlib `csv` module**. Reasons:
  - Image size: this PR's dependencies add 4.2 MB to the API image (measured: 411.8 MB → 416.0 MB); pandas plus numpy were estimated at about 40 MB in the M1 plan (R8).
  - CVE surface: pandas brings numpy and a large native code base that we would have to track, for features we don't use (we only need cell values row by row).
  - numpy's thread pools conflict with the child's `RLIMIT_NPROC` 0 (see "Isolation").
  - The image check (`smoke-images.sh`) fails if `lxml`, `pandas` or `numpy` is installed in the API image.
- **Detection by bytes** (`detect.py`, `archive.py`, `cfb.py`):
  - A ZIP is XLSX/XLSM only when `[Content_Types].xml` (read with defusedxml) gives `xl/workbook.xml` a workbook or macro-enabled workbook content type.
  - `.xlsb` (`xl/workbook.bin`), `.ods` (ODF `mimetype`) and templates (`.xltx`/`.xltm`) are `unsupported_spreadsheet`; any other ZIP (`.docx`, a plain archive) is `unsupported_type`.
  - A CFB file (legacy Office) is read only as far as its directory entry names, within a bounded number of sectors and with no new dependency: a `Workbook`/`Book` stream is `.xls` (`unsupported_spreadsheet`); an `EncryptedPackage` stream is a password-protected workbook (`encrypted_spreadsheet`; an encrypted Word file looks the same). Any other CFB is `unsupported_type`.
  - CSV is tried last, with our own linear delimiter sniffer (`,` `;` tab `|` counted outside quotes over the first 50 records of the first 64 KB). `csv.Sniffer` is regex-based and slow on hostile input. Markup or JSON (`<`, `{` first) and text with control characters are not CSV.
- **Refused formats get a clear message** (Q-PR5-5(c), `messages.py`):
  - `unsupported_spreadsheet`: "This spreadsheet format isn't supported. Save it as .xlsx or CSV and upload again."
  - `encrypted_spreadsheet`: "This workbook is password-protected. Remove the password, save it as .xlsx or CSV, and upload again."
  - `too_many_rows`: "This spreadsheet has more than 2,000 rows. Split it and upload the parts."
- **ZIP caps before anything is inflated** (`archive.py`): the end-of-central-directory record is read first, so ZIP64, multi-disk archives, more than 500 entries or a central directory over 500 KB are refused before `zipfile` builds its entry list. Then every entry: no encryption, only stored or deflated, no duplicate names, at most 64 MB uncompressed each and 256 MB together, as declared (`zipfile` never inflates past the declared size and checks the CRC, so a lying size can't produce more). Shared strings at most 32 MB, `[Content_Types].xml` at most 1 MB. Structure problems are `invalid_file`, sizes over a cap `document_too_large`.
- **XML only through defusedxml, fail closed** (Q-PR5-5(d)):
  - `defusedxml` is a runtime dependency. At import, `xlsx.py` checks that `openpyxl.xml.DEFUSEDXML` is true, `openpyxl.xml.LXML` is false, and both entry points openpyxl uses (`iterparse`, `fromstring`) come from defusedxml; otherwise the parser raises `parse_failed` and never reads a workbook. The image check asserts the same in the built image.
  - openpyxl's defusedxml calls forbid entities and external references but still allow a DTD. So before openpyxl runs, **`refuse_dtds` parses the prolog of every entry that could be XML, with `forbid_dtd=True`**. Whether an entry could be XML is decided by its first bytes, never its name: openpyxl finds parts by content type and relationship, so shared strings can be named `xl/strings.bin`. UTF-8 (BOM optional) whose first non-space byte is `<`, and anything that looks like UTF-16, is checked; images and `vbaProject.bin` are not. A DTD anywhere is `invalid_file`.
  - Our own XML reads (`[Content_Types].xml`, the sheet pre-pass) use defusedxml directly with DTDs forbidden.
  - Tests: billion laughs, quadratic blowup and XXE (`SYSTEM "file:///…"`, external DTD) in `[Content_Types].xml`, `workbook.xml`, the sheet XML and `sharedStrings.xml`, and under a non-XML name: `invalid_file`, fast, nothing fetched.
- **openpyxl settings** (`xlsx.py`): `read_only=True`, `data_only=True`, `keep_links=False` (external workbooks never read), `keep_vba=False` (macros never read or run; `macros_ignored` for XLSM or a VBA project). **Chart sheets are never read, whatever their part path** (`sec` M1): openpyxl picks chart sheets by relationship type wherever the part lives, so filtering an `xl/chartsheets/` path wasn't enough; openpyxl's chart-sheet reader is replaced by one that skips the sheet, so their drawings and images are never parsed. More than 64 sheets (`MAX_SHEETS`) is `document_too_large`, checked on `workbook.xml` before openpyxl opens any sheet (`sec` M2). The declared `<dimension>` is never trusted (`reset_dimensions()`); the read is bounded by the pre-pass instead.
- **Hidden-cell pre-pass** (`xlsx_scan.py`, Q-PR5-5(b)): openpyxl's read-only mode doesn't expose row or column visibility, so each sheet's XML is streamed once with defusedxml `iterparse` (elements cleared as it goes, memory flat) before openpyxl reads it.
  - Rows and columns are hidden **the way Excel hides them** (`sec` M3, L1): a row with `hidden`, or a height under 0.5 points; with `<sheetFormatPr zeroHeight="1">` every row without a custom height; with a default height of 0 every row without its own. A column with `hidden`, or a width under 0.5; with a default width of 0 every column no `<col>` covers. Autofilter-hidden rows carry `hidden="1"`.
  - **Every hidden row and column is dropped before the table is built, data or not** (`sec` L2), so it never reaches the wire, the model or `raw_text`. Warning `hidden_cells_ignored`, counting those that held data.
  - It records the last row and column with visible data, which bound openpyxl's read. Visible data below row 20,000 is `too_many_rows`; a read area (last row × last column, empty cells included) over 2,000,000 cells (`MAX_CELLS_READ`) is `document_too_large`: two cells at A1 and XFD20000 would otherwise cost ~327M cells, about 90 s (`sec` M2).
  - Memory stays flat: elements are cleared as they are read, outside `sheetData` too (`sec` L5).
  - It follows openpyxl's numbering (a `<row>` without `r` is the previous + 1, a `<c>` without `r` the previous column + 1) and refuses rows or cells out of order or beyond Excel's grid (`invalid_file`), since openpyxl would silently drop or overwrite them.
  - Hidden sheets are never read (`hidden_sheets_ignored` when one holds data). Only the **first visible sheet with data** is read; if other visible sheets hold data, `other_sheets_ignored` and their names go on the table (Q-PR5-5(a)): format and control characters removed, one line, at most 31 characters (Excel's limit), at most 255 names, re-checked by the parent, never logged (count only) and never sent to the model. They reach the reviewer through the warning's `details` (below).
- **Formulas: cached value only** (Q-PR5-5(e)). A formula is never evaluated and its text is never read. With `data_only=True` an uncached formula looks like an empty cell, so the pre-pass counts formula cells (`<f>`) without a value (`<v>`) in visible rows and columns: they stay empty and add `formula_without_value`. CSV: a cell starting with `=` is plain text (formula injection matters only for our own CSV export, M5).
- **Cell rendering in the child**: integers as digits (zero-padded when the number format is all zeros, so `00123` survives), other numbers with at most 15 significant digits and no exponent, dates as ISO `YYYY-MM-DD` (with a time if there is one), booleans `TRUE`/`FALSE`, error values as written. Cell text: line breaks → LF, NUL and other controls (but tab and LF) removed, **format characters (Unicode Cf: bidi overrides, zero-width characters, BOM, soft hyphen) removed** (`sec` L3), lone surrogates replaced, whitespace-only → empty.
- **CSV** (`csvfile.py`, Q-PR5-4 not answered yet; the plan's recommendation is built): UTF-8 (a BOM stripped), UTF-16 with a BOM, otherwise Windows-1252 with `encoding_guessed`. A BOM that lies is `invalid_file`; a NUL or another control character means it isn't text. `csv.field_size_limit` is set to the cell cap for the read and restored after; a longer field is `document_too_large`. Records are counted while streaming.
- **Caps** (`limits.py`, added to those above):
  - 2,000 non-empty rows (`too_many_rows`, Q12) and 20,000 rows read, empty ones included, so a single cell far down the sheet can't make us walk a million empty rows (`too_many_rows`).
  - 64 columns holding data, 32,767 characters per cell (Excel's limit), 1,000,000 characters per table (`document_too_large`).
  - XLSX: a read area of at most 2,000,000 cells (`MAX_CELLS_READ`) and at most 64 sheets (`MAX_SHEETS`) (`document_too_large`, `sec` M2).
  - Excel's grid (column XFD, row 1,048,576): a reference beyond it is `invalid_file`.
  - ZIP: 500 entries, 64 MB per entry, 256 MB total, 32 MB shared strings (above).
- **The table** (`table.py`, `ParsedDocument.table`): only non-empty rows and only columns that hold data, each with its source number (strictly increasing), one cell per kept column. `text` is None for a spreadsheet, and `to_document_input()` refuses one: a spreadsheet's cells never go to `extract_po`, only a sample goes to `map_columns` (`extract_spreadsheet`).
- **Wire v2** (`wire.py`): the table crosses from the child as JSON and the parent re-checks it like the rest of the reply: the row, column, cell and table caps, increasing row and column numbers, cleaned cells, the sheet-name rules, and a table exactly for the spreadsheet kinds (`xlsx`, `csv`).
- **Header values by reference** (Q-PR5-3): the mapping model (`map_columns`) returns, for a header field, the cell it is in and the exact characters; code checks they are a non-blank substring of that cell in the sample **made of whole tokens** (`sec` M5: never a piece of a number or an id, such as `345.00` of `12,345.00` or `45000` of `4500012345`, and a total can't leave out a sign printed next to it) and copies them. `ExtractionResult.sources` keeps the source cell (row, column) of each header fact and address line, for the reviewer. The model can still point at a wrong but real whole-token cell (Follow-up M1-SHEET-HEADER-CELL). Dates are parsed by code (ISO or US `M/D/YY`), keeping the raw text; `currency` must be a 3-letter code. Addresses are only the referenced cells' text as `raw_text`, never split into fields. So a cell can steer *which* cell fills a field, never *what* the field says. The mapping and the line building are covered in ADR 0011's note on `call_with_retry` and in `app/extraction/column_mapping.py` / `spreadsheet.py`.
- **Warnings with details** (owner decision 2026-11-21): the extraction's warnings for a spreadsheet carry typed, bounded `details`, checked on construction. Details are document content: shown to the reviewer, never logged. Storage and display come with PR 14 / M3 (Follow-up M1-SHEET-STORE).
  - `other_sheets_ignored`: the other sheets' names; `hidden_cells_ignored`: the hidden row and column counts; `formula_without_value`: the count.
  - **`rows_skipped`** (owner, `sec` M4): no non-empty row disappears silently. Rows the mapping leaves out (footer rows, and every non-empty row above `first_data_row`) are listed with their row numbers and text (cells joined with ` | `, like `raw_text`). The only exceptions are rows a `header_values`/`addresses` reference uses and the single heading row directly above the data (text and no number in a mapped numeric column; with none mapped, no numeric cell). A title the mapping ignores is listed too: noisier, but nothing is dropped unseen.
  - `extract_spreadsheet(..., input_warnings=)` takes the `ParsedDocument`'s warnings, so a sheet warning survives even when no name survived cleaning; the worker must pass them (Follow-up M1-SHEET-INPUTWARN).
- **Logging**: `document.parsed` adds the table's row and column counts (`table_rows`, `table_columns`) next to the warning codes; never a cell or a sheet name.
- **Dependencies** (runtime, pinned `~=`; each release was more than two weeks old):
  - `openpyxl~=3.1.5` (released 2024-06-28)
  - `defusedxml~=0.7.1` (2021-03-08)
  - `et-xmlfile` 2.0.0 (2024-10-25), openpyxl's own dependency, locked in `uv.lock`
  - No new dev dependency: every test workbook and CSV is built in code; no binary test file is committed.

## Consequences
- The worker (PR 14) calls `parse_isolated` through `asyncio.to_thread`. Its job lease must cover the 60 s parse plus the LLM deadline (ADR 0011).
- Small hostile files can still use the full 60 s, for example dense text operators or 200,000 MIME parts. That costs worker time, not safety. PR 13/14 limit parses per org and run at most (container memory ÷ 2 GiB) children at once (Follow-up M1-PARSE-LOAD).
- The API (PR 13) runs detection and the size cap on upload too (415/413) but never the parsers. Parsing happens only in the worker's child process.
- Up to 20 page images per request is real input-token cost. It is measured in PR 9's live eval, and prompt caching is M1-CACHE.
- Parser CVEs: versions are pinned and upgraded deliberately. Dependabot comes with G1. An openpyxl upgrade must keep the import-time defusedxml check and `refuse_dtds` passing (they depend on openpyxl internals: `openpyxl.xml.DEFUSEDXML`/`LXML`, `ExcelReader.valid_files`, `_worksheet_path`).
- Spreadsheets cost one small Haiku call instead of a Sonnet extraction, and the values can't be invented. In exchange, what the model can get wrong is *where* things are: a wrong column or header cell gives visibly wrong (but real) data for the reviewer, and a row wrongly taken for a footer is not a line but is listed in `rows_skipped` (Follow-ups M1-SHEET-*). PR 6 adds eval cases for each header shape, footers and hidden cells.
- Hidden rows and columns are left out on purpose; the reviewer must be told (M3-SOURCE).
- Starting a child costs about 0.5–1 s per document, which is small next to the LLM call.
